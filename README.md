# SMS Number Bot

بوت Telegram لبيع أرقام استقبال SMS، مع أقسام اختيارية للألعاب وتطبيقات الـ SMM وشحن الرصيد.

> **تنبيه:** لا تضع مفاتيح API أو توكن Telegram داخل Git. انسخ `.env.example` إلى `.env` واملأ القيم على الخادم فقط.

## التشغيل المحلي

يتطلب Python 3.11 أو أحدث:

```bash
python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# عدّل .env
python bot.py
```

المتغيرات الأربعة التالية مطلوبة لبدء البوت:

- `BOT_TOKEN`
- `BOT_USERNAME`
- `ADMIN_IDS` — آيديات Telegram مفصولة بفواصل
- `ADMIN_NOTIFY_CHAT_ID` — مجموعة/قناة خاصة لإشعارات الإدارة

حالات المحادثة تعمل افتراضياً في الذاكرة. للإنتاج يمكن وضع `REDIS_URL` لتبقى
حالات الشحن والطلب محفوظة بعد إعادة تشغيل البوت.

## التشغيل عبر Docker

```bash
cp .env.example .env
# عدّل .env
docker compose up -d --build
```

يتم حفظ SQLite في `bot_database.db` داخل مجلد `data/`، وتحفظ Redis حالات المحادثة بشكل دائم. خذ نسخة احتياطية قبل أي ترقية.

## الإعداد بعد أول تشغيل

1. أضف البوت كأدمن في قناة/مجموعة إشعارات الإدارة.
2. أضف مزود SMS واحداً على الأقل في `.env`.
3. من لوحة الأدمن أضف الدول والخدمات والأسعار.
4. لأقسام الألعاب أو SMM: أضف API provider، اختر البروتوكول المناسب، اختبر الاتصال، نفّذ المزامنة، ثم أنشئ الأقسام والمنتجات من الخدمات المسحوبة.
5. فعّل طرق الدفع بعد وضع عناوين المحافظ واختبارها بمبالغ صغيرة.

## ربط مزود جديد

يدعم النظام حالياً:

- `SMM V2`: مزودو SMM القياسيون عبر `action=balance/services/add/status`.
- `Games JSON`: مزود REST JSON افتراضي لمسارات `/balance` و`/services` و`/order`.
- `Custom JSON`: مزود API مخصص مع مسارات وحقول قابلة للتغيير من Wizard الأدمن.

في `Custom JSON` يمكن تحديد `endpoints` و`fields` و`service_fields` و`order_payload`
داخل إعداد JSON الخاص بالمزود. بعد اختبار الاتصال، تظهر خدماته في لوحة الأدمن
ويمكن اختيار الخدمة المسحوبة مباشرة عند إنشاء المنتج، مع حفظ رابطها بالمزود
لتتعطل المنتجات تلقائياً إذا حذف المزود الخدمة.

## الميزات الحالية

- كتالوج ديناميكي للألعاب والتطبيقات وSMM.
- بحث المستخدم عن المنتجات ومفضلة شخصية مع حذف سريع.
- سوق طلبات: المستخدم يقترح خدمة غير موجودة، والمستخدمون يصوتون عليها حتى تصل للإدارة.
- عرض تفاصيل الطلبات للمستخدم.
- مركز إدارة لطلبات الألعاب/SMM وأرقام SMS وطلبات الشحن للأدمن.
- إكمال يدوي أو استرجاع آمن مع تأكيد قبل التنفيذ.
- سجل تغييرات الإدارة مع تصفح الصفحات.
- نظام تذاكر دعم داخل البوت مع ردود وحالات ومتابعة من الأدمن.
- لوحة صحة النظام مع حالة المزودين والمدفوعات بدون كشف الأسرار.
- تحكم ديناميكي بتفعيل وإيقاف طرق الدفع.
- برنامج ولاء كامل: مستويات، نقاط على المشتريات، تسجيل يومي، سلسلة أيام واستبدال النقاط لرصيد.
- منتجات رقمية بمخزون مشفّر وتسليم فوري (قسائم/تراخيص شرعية).
- عروض زمنية وFlash Sales ديناميكية مع أفضل خصم تلقائي وعدّاد استخدامات.
- لوحة إدارة وإعدادات خاصة ببرنامج الولاء والمخزون والعروض.
- سجل مالي مع حماية من تكرار الدفعات وتحويلات ذرّية.
- مزامنة الخدمات من مزودي API ومراقبة الطلبات والفواتير.

المنتج الذي لا يملك مزود API فعالاً يجب أن يكون من نوع المخزون الرقمي حتى
يُسلّم كوداً أو ترخيصاً مشفراً فورياً؛ أما المنتج اليدوي بلا آلية تسليم فلا يمكن
شراؤه، حتى لا يُخصم الرصيد على طلب غير قابل للتنفيذ.

## فحص الكود

```bash
python -m compileall -q .
```

لا تشغّل مدفوعات الإنتاج قبل اختبار الملكية، منع تكرار الدفع، واسترجاع الرصيد في بيئة تجريبية.

## المنتجات الرقمية والمحتوى المسموح

يمكن إنشاء منتجات مثل اشتراكات الذكاء الاصطناعي، القسائم، التراخيص، وخدمات
الترفيه الرسمية عبر مزود API أو مخزون مشفّر تملكه بشكل قانوني. لا يدعم النظام
بيع جلسات Telegram، رموز الدخول، كلمات المرور، أو الحسابات المسروقة؛ لخدمات
Telegram استخدم المنتجات الرسمية مثل Premium أو أرقاماً قانونية بدون تسليم
ملفات جلسة أو رموز وصول.
